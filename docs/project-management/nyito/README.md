## Evidence handling

Capture real results with task/test ID, build/commit, environment, actual date, author, result and limitation. Preserve raw outputs and earlier failures. Use synthetic data. Keep credentials and personal attendance records out of public Git. Check links from another permitted account. Screenshots support results; calendar invitations do not prove attendance, and browser mobile layouts do not prove physical Android testing.

## Azure work-item template

Title: [task ID] outcome. Description: scope and deliverable. Acceptance: tracker criterion. Assigned owner/deadline: confirmed with owner. Dependencies: linked work items. Evidence: file/test/PR URLs. Review: reviewer and decision. Blocker: next action and owner. Use the existing project; do not create duplicate boards. Capture a meaningful overview, a detailed work item and an actual update history after doing the work.
