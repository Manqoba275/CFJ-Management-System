# Demonstration preparation

Use this as a recording plan after the outstanding implementation and phone checks are complete. Do not narrate unfinished features as working.

1. Introduce The Forge and explain the website, Kotlin Android app, API and database.
2. Demonstrate the current member flow: sign in, edit a profile, book and cancel a class. State whether the screen is using browser demo data or the shared API.
3. Demonstrate the local Oracle profile separately: load, save and read the same committed profile in another browser. Keep tokens hidden.
4. Show the build/test evidence and explain its limits. Unit tests and browser screenshots do not replace a physical-phone demonstration.
5. Once hosted authentication, the remaining data flows and phone testing work, record them on the physical phone. Show the online authentication, API and database data required by the brief without exposing credentials.
6. Explain remaining limitations honestly, then reference the repository, user guide and actual team evidence.

Before recording, close unrelated windows, use fictional records, check audio, rehearse the steps and confirm that all supplied links are accessible to the lecturer. Do not submit a video that shows only the current browser demonstration as if it were the finished Android system.
